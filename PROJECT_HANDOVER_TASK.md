# Промт: підготовка повного пакету передачі проєкту EuroClub App

**Мета:** зібрати все необхідне, щоб застосунок (код + інфраструктура + права)
можна було формально визнати активом і/або передати новій команді/власнику без втрати
контексту.

---

## 1. Специфікація (технічна)

- [ ] `PRICING_SPEC.md` — вже є (ціноутворення, три типи замовлень)
- [ ] `ARCHITECTURE.md` — стек, структура папок, ключові файли, потік даних
      (Firestore-колекції, Cloudflare Worker'и, зовнішній API бекенду)
- [ ] Схема Firestore-колекцій — `device_tokens`, `order_registry`, `open_returns`,
      `settings`, плюс майбутня `notifications` — з описом полів кожної
- [ ] `API_NOTES.md` — довідка по бекенд-ендпоінтах (`mod=apimobile`, `opr=...`),
      коди статусів, особливості (uidkey, app=1/2 тощо) — частина вже накопичена,
      потребує оформлення в окремий файл

## 2. Функціональний опис кожного сценарію

- [ ] Флоу реєстрації/входу (гість vs акаунт)
- [ ] Пошук рейсу → бронювання → оплата (три варіанти: one-way, round-trip, відкрита дата)
- [ ] Знижки пасажирів (як обираються, як застосовуються)
- [ ] Видалення акаунту (вже описано для Apple review — можна перевикористати)
- [ ] Push-сповіщення (поточний стан + запланована нова архітектура)
- [ ] Скасування/відновлення замовлення, доплата
- [ ] Адмін-панель: кожен розділ (Push-розсилки, Автопарк, Маршрути, Сторінки, Вхідні,
      Звіт і сегменти, Реєстр замовлень, Налаштування) — що робить, хто ним користується

## 3. Код + специфікація коду

- [ ] Репозиторії в чистому стані (без незлитих гілок, без тестових секретів)
- [ ] `FIXES.md` — журнал усіх виправлень (вже ведеться)
- [ ] Коментарі в коді на ключових рішеннях — вже частково є (напр. `PRICING_SPEC.md`
      посилання в коментарях `Booking.tsx`)

## 4. Усі платформи/сервіси, які використовуються

- [ ] `HANDOVER.md` — вже є: GitHub, Vercel, Firebase, Cloudflare, App Store Connect,
      Google Play Console, backend eclub.com.ua

## Що, можливо, пропущено (додав сам)

- [ ] **Домен eclub.com.ua** — хто власник реєстрації домену? Це критичний актив сам
      по собі, окремо від коду застосунку.
- [ ] **Платіжні провайдери (LiqPay, Stripe)** — на кого зареєстровані мерчант-акаунти?
      Без доступу до них новий власник не зможе отримувати платежі чи навіть бачити
      транзакції.
- [ ] **Права на бренд/лого** — чи зареєстрована торгова марка "EuroClub"? (згадували
      раніше — це окремо від коду)
- [ ] **Права на дизайн/контент** — хто автор іконки застосунку, скріншотів для App
      Store, маркетингових текстів? Якщо робив підрядник — чи є в тебе майнові права?
- [ ] **Вартість підтримки/хостингу** — поточні тарифні плани (Firebase, Vercel,
      Cloudflare, Apple Developer $99/рік, Google Play $25 одноразово) — новий власник
      має розуміти операційні витрати.
- [ ] **Контакти підтримки** — `eclubbus24@gmail.com` (видалення акаунту),
      `euroclubbus@gmail.com` (фіксація дати) — хто матиме до них доступ далі?
- [ ] **Юридична особа-власник акаунтів** — App Store Connect показує "Eurocclub LLC" —
      чи це та сама юрособа, що й власник домену/платіжних акаунтів? Розбіжність тут
      ускладнює цілісну передачу.
- [ ] **Договори з підрядниками** (backend-розробник) — чи є письмова угода про
      передачу майнових прав на бекенд-частину коду компанії?
- [ ] **Persistent/тестові дані** — чи потрібно передавати історичні дані
      (`order_registry`, `trip_reports`) новому власнику, чи почати з чистого Firestore?
