# Сповіщення — план для iOS

**Статус: ЗАПЛАНОВАНО, ще не реалізовано** (звук — вже зроблено, потребує ручного кроку в
Xcode, див. нижче). Записано 10.08.2026 за описом Кепа, чекає команди "Виконуй" на решту.

---

## Проблема зараз

Записи в "Мої сповіщення" з'являються лише якщо Capacitor реально спіймав push-подію на
пристрої. Якщо застосунок закритий/подія не спрацювала — запису нема або він порожній.

## Нова архітектура (спільна для всіх платформ)

1. При відправці повідомлення з адмінки — пишеться запис **напряму у Firestore** (нова
   колекція `notifications/{userId}/messages/{id}`) через внутрішній метод адмінки —
   незалежно від push.
2. Push шлеться **окремо**, тим самим Cloudflare Worker'ом (`euroclub-push-sender`) —
   паралельний виклик, не залежний від запису.

## Що специфічно для iOS

### ✅ Частково зроблено (10.08): звук
- Файл `ios/App/App/Sounds/notification_sound.caf` — власний звук сповіщення (наданий
  Кепом, сконвертований з mp3 в caf через ffmpeg).
- Worker шле в APNs payload: `aps: { alert: {...}, sound: 'notification_sound.caf' }`.
- **⚠️ НЕ ПРАЦЮЄ, поки не зроблено вручну в Xcode:** файл лежить у git, але Xcode не
  включить його у збірку автоматично. Потрібно: відкрити Xcode → правою кнопкою на папку
  `App` → **Add Files to "App"...** → обрати `Sounds/notification_sound.caf` → переконатись,
  що ввімкнено **"Copy items if needed"** і **"Add to targets: App"**. Без цього кроку iOS
  тихо відкотиться на системний звук за замовчуванням, без помилки — виглядатиме, ніби
  нічого не змінилось.
- Вібрація на iOS йде автоматично разом зі звуком (системна поведінка), окремо не
  налаштовується — додаткового коду не потребує.

### ⬜ Бейдж на іконці застосунку (system badge)
iOS має **єдиний стандартний механізм** — число на іконці застосунку через `aps.badge` у
APNs payload АБО через клієнтський виклик (Capacitor Badge plugin). Два підходи:
- **Через APNs (`aps.badge: N`)** — Worker мусить знати ТОЧНЕ число непрочитаних для
  конкретного юзера в момент відправки push (складніше при масовій розсилці — треба
  запит до Firestore на кожного отримувача перед відправкою).
- **Через клієнтський плагін** (простіше, рекомендовано) — застосунок сам оновлює бейдж
  локально, читаючи лічильник непрочитаних з Firestore (той самий, що на дзвінку в UI) —
  синхронізується незалежно від push. Потрібен `@capawesome/capacitor-badge` (чи аналог) —
  **ще не встановлений у проєкті**.

### ⬜ Список "Мої сповіщення"
Читає нову Firestore-колекцію, показує тему в списку, тап відкриває деталі (тема + текст).

### ⬜ Бейдж на дзвінку (в UI застосунку)
Червоний кружечок з числом непрочитаних у нижній навігації — рахується з Firestore.
