## Проблема зараз

Записи в "Мої сповіщення" з'являються лише якщо Capacitor реально спіймав push-подію на
пристрої (`pushNotificationReceived`/`pushNotificationActionPerformed`). Це ненадійно:
якщо застосунок закритий або подія не спрацювала — запису або нема, або він порожній.

**Важливий нюанс саме для PWA:** `registerPushToken()` (`src/push.ts`) вже зараз пропускає
реєстрацію push-токена, якщо `!Capacitor.isNativePlatform()` — тобто **PWA взагалі не
отримує нативний push** (ні FCM, ні APNs). Це означає:
- Звук/вібрація/badge на іконці застосунку — **не стосуються PWA** (нема самого механізму
  push, немає що озвучувати)
- Для PWA актуальна лише частина плану: запис сповіщення + бейдж на дзвінку в UI

## Нова архітектура (спільна для всіх платформ)

1. Коли адмінка/бекенд надсилає повідомлення — пишеться запис **напряму у Firestore**
   (нова колекція, напр. `notifications/{userId}/messages/{id}`) через внутрішній метод
   адмінки — незалежно від push і від того, чи спіймав пристрій подію.
2. Push (де є) шлеться **окремо**, тим самим Cloudflare Worker'ом — паралельний, не
   залежний виклик.

## Що специфічно для PWA

- **Список "Мої сповіщення"** — читає ту саму нову Firestore-колекцію, показує тільки тему
  в списку, тап відкриває повний перегляд (тема + текст). Однаково для всіх платформ.
- **Бейдж на дзвінку (в UI)** — червоний кружечок з числом непрочитаних, рахується з
  Firestore-колекції. Працює на PWA так само, як і в застосунках.
- **Бейдж на іконці застосунку (system badge)** — для PWA це не нативна іконка застосунку
  (немає інсталяції в системний App Store), тому цей пункт плану **не застосовується** до
  PWA взагалі. Є експериментальний Badging API в деяких браузерах (`navigator.setAppBadge()`)
  для встановлених PWA (Chrome desktop, деякі Android), але підтримка неповна й нестабільна
  — не братися за це, поки не буде окремого запиту.
- **Звук/вібрація сповіщення** — не застосовується (PWA не отримує push).
