## Позначення платформи для бекенду (app=1/app=2)

Кожен запит на бекенд містить поле `app`, за яким бекенд розрізняє, з якої платформи
прийшов запит:

| Платформа | Значення `app` |
|---|---|
| PWA (веб) | `1` |
| Android | `1` |
| iOS | `2` (завжди, включно з iPad) |

Визначається автоматично (`src/api/auth.ts`, `APP_PLATFORM`) через `navigator.userAgent` —
PWA і Android наразі НЕ розрізняються між собою (обидва `1`), бекенд бачить лише "iOS чи ні".
Домовлено з бекенд-розробником 04.08. Якщо замовнику потрібна окрема мітка для PWA —
це вимагає додаткової домовленості з бекенд-розробником про нове значення (напр. `3`).

## "Бали" (бонусні очки) — прихована функція, лише для PWA

UI для нарахування/списання бонусних балів (чекбокс промокоду на екрані бронювання, чекбокс
списання балів на екрані успішного замовлення) **прибрано з усіх платформ перед публікацією**
— функціонал ще не готовий на бекенді. Не є частиною жодного опублікованого білда (Android/
iOS), лишався лише в коді PWA-версії, і то прихованим.

**Статус на момент здачі:**
- UI-блоки видалені з `Booking.tsx` (промокод) і `OrderSuccess.tsx` (списання балів) —
  видимого сліду в застосунку немає, потрібно вручну повертати компоненти назад у код, коли
  бекенд буде готовий.
- Невирішено: чи існує в API поле "бали в очікуванні" в особистому кабінеті — не перевірено.
- Невирішено: чому бали не списувались навіть коли баланс показувався доступним — потрібен
  живий лог запиту/відповіді `addbonus`, не діагностовано.
- Промокоди для гри — окрема задача: наразі створюються вручну (Кеп дублює код в
  eclub.com.ua і в системі гри), в майбутньому потрібен API для автоматичного створення
  промокодів з боку гри.

**Для замовника:** ця функція НЕ готова до продакшену — не активувати без окремого
узгодження з бекенд-розробником.
